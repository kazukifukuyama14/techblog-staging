# 🛠️ AWS + Hugo テックブログ 運用・保守手順書

## 📋 概要

本ドキュメントは、AWS と Hugo を組み合わせた静的テックブログの運用・保守に関する手順を定義します。日常的な運用作業から障害対応まで、体系的に整理しています。

## 🎯 運用・保守の基本方針

### 運用の原則

- **自動化優先**: 可能な限り CI/CD とスクリプトで自動化

- **段階的対応**: 問題の段階的な切り分けと対応

### 保守の原則

- **予防保守**: 定期的な点検による問題の未然防止
- **計画保守**: 計画的な更新・改善の実施
- **緊急対応**: 障害発生時の迅速な対応体制

## 🔍 日常監視項目

### 1. サイトの可用性監視

**監視項目**:

- サイトの応答時間
- エラー率
- ダウンタイム

**監視項目**:

```bash
# CloudWatchでの監視設定
aws cloudwatch put-metric-alarm \
  --alarm-name "WebsiteResponseTime" \
  --alarm-description "Website response time alarm" \
  --metric-name "ResponseTime" \
  --namespace "AWS/CloudFront" \
  --statistic "Average" \
  --period 300 \
  --threshold 2000 \
  --comparison-operator "GreaterThanThreshold"
```

#### アラート設定

- 応答時間が 2 秒を超えた場合
- エラー率が 5%を超えた場合
- サイトが 10 分以上応答しない場合

### 2. セキュリティ監視

**監視項目**:

- 不正アクセスの検知
- セキュリティグループの変更
- ※ staging 環境では SSL 証明書の監視は行わない

**監視項目**:

```bash
# CloudTrailでのAPI呼び出しログ確認
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=DeleteBucket

# 既存IAMユーザーの権限確認
aws iam list-attached-user-policies --user-name techblog-staging
```

### 3. コスト監視

**監視項目**:

- S3 のストレージ使用量
- CloudFront の転送量
- S3 のストレージ使用量

**監視項目**:

```bash
# S3バケットの使用量確認
aws s3 ls s3://techblog-staging-bucket --recursive --human-readable --summarize

# CloudFrontの転送量確認
aws cloudwatch get-metric-statistics \
  --namespace "AWS/CloudFront" \
  --metric-name "BytesDownloaded" \
  --dimensions Name=DistributionId,Value=YOUR_DISTRIBUTION_ID \
  --start-time 2024-01-01T00:00:00Z \
  --end-time 2024-01-31T23:59:59Z \
  --period 86400 \
  --statistics Sum
```

## 📝 日常運用作業

### 1. 記事の投稿・更新

#### 新規記事の投稿

```bash
cd hugo-site

# 新規記事の作成
hugo new posts/new-article.md

# 記事の編集（VS Code等で編集）
code content/posts/new-article.md

# ローカルでの確認
hugo server -D

# 記事の投稿（Gitでコミット・プッシュ）
git add .
git commit -m "feat: 新規記事の追加"
git push origin main
```

#### 既存記事の更新

```bash
# 記事の編集
code content/posts/existing-article.md

# 変更の確認
git diff

# 変更のコミット・プッシュ
git add .
git commit -m "fix: 記事の内容を更新"
git push origin main
```

### 2. テーマの更新

#### テーマの更新手順

```bash
cd hugo-site

# テーマの最新版を取得
git submodule update --remote --merge

# 変更の確認
git status

# 変更のコミット
git add themes/
git commit -m "chore: テーマを更新"
git push origin main
```

#### カスタムテーマの管理

```bash
# カスタムテーマの作成
mkdir themes/custom-theme
cp -r themes/PaperMod/* themes/custom-theme/

# 設定ファイルの更新
# config.tomlでtheme = "custom-theme"に変更
```

### 3. バックアップ・復旧

#### 定期バックアップ

```bash
# Hugoサイトのバックアップ
cd hugo-site
tar -czf ../backup/hugo-site-$(date +%Y%m%d).tar.gz .

# Terraform設定のバックアップ
cd ../terraform
tar -czf ../backup/terraform-$(date +%Y%m%d).tar.gz .

# Gitリポジトリのバックアップ
cd ..
git clone --mirror .git backup/repo-backup-$(date +%Y%m%d)
```

#### 復旧手順

```bash
# Hugoサイトの復旧
cd hugo-site
rm -rf *
tar -xzf ../backup/hugo-site-20240101.tar.gz

# Terraform設定の復旧
cd ../terraform
rm -rf *
tar -xzf ../backup/terraform-20240101.tar.gz

# インフラの再構築
terraform init
terraform plan
terraform apply
```

## 🚨 障害対応手順

### 1. サイトが表示されない場合

#### 緊急時の対応手順

1. **状況の確認**

   ```bash
   # サイトへのアクセス確認
   curl -I http://localhost:1313

   # CloudFrontの状態確認
   aws cloudfront get-distribution --id YOUR_DISTRIBUTION_ID
   ```

2. **S3 バケットの確認**

   ```bash
   # ファイルの存在確認
   aws s3 ls s3://techblog-staging-bucket --recursive
   ```

3. **バケットポリシーの確認**

   ```bash
   # バケットポリシーの確認
   aws s3api get-bucket-policy --bucket techblog-staging-bucket
   ```

4. **CloudFront のキャッシュ無効化**

   ```bash
   # キャッシュの無効化
   aws cloudfront create-invalidation \
     --distribution-id YOUR_DISTRIBUTION_ID \
     --paths "/*"
   ```

5. **CloudFront の設定確認**

```bash
# CloudFrontの設定確認
aws cloudfront get-distribution-config --id YOUR_DISTRIBUTION_ID
```

#### 復旧後の確認事項

- [ ] サイトが正常に表示される
- [ ] すべてのページがアクセス可能
- [ ] 画像や CSS が正しく読み込まれる
- [ ] ローカル環境での動作確認が完了している

### 2. SSL 証明書の問題

#### 問題の切り分け

**※ staging 環境では SSL 証明書の問題は発生しません**:

```bash
# 本番環境でのみ使用するコマンド例
# aws acm describe-certificate \
#   --certificate-arn YOUR_CERTIFICATE_ARN

# aws route53 list-resource-record-sets \
#   --hosted-zone-id YOUR_HOSTED_ZONE_ID \
#   --query 'ResourceRecordSets[?Type==`CNAME`]'
```

#### 対処方法

**※ staging 環境では SSL 証明書の問題は発生しません**:

1. **本番環境での DNS 検証の再実行**

```bash
# 証明書の再検証（本番環境でのみ使用）
# aws acm resend-validation-email \
#   --certificate-arn YOUR_CERTIFICATE_ARN
```

1. **本番環境での手動 DNS 検証**
   - Route 53 で検証用レコードを手動で作成
   - 検証完了まで待機（最大 24 時間）

#### パフォーマンス測定

```bash

  --namespace "AWS/CloudFront" \

  --end-time 2024-01-01T23:59:59Z \
```

## 📊 監視・ログ管理

### 1. CloudWatch ログの設定

#### ロググループの作成

```bash
# CloudWatchロググループの作成
aws logs create-log-group \
  --log-group-name "/aws/cloudfront/techblog-staging"

# ログ保持期間の設定
aws logs put-retention-policy \
  --log-group-name "/aws/cloudfront/techblog-staging" \
  --retention-in-days 30
```

#### ログの確認

```bash
# ログストリームの一覧
aws logs describe-log-streams \
  --log-group-name "/aws/cloudfront/techblog-staging"

# ログイベントの取得
aws logs filter-log-events \
  --log-group-name "/aws/cloudfront/techblog-staging" \
  --start-time 1640995200000 \
  --end-time 1641081600000
```

### 2. アラートの設定

#### 重要なアラート

```bash
# サイトダウンアラート
aws cloudwatch put-metric-alarm \
  --alarm-name "WebsiteDown" \
  --alarm-description "Website is down" \
  --metric-name "Requests" \
  --namespace "AWS/CloudFront" \
  --statistic "Sum" \
  --period 300 \
  --threshold 1 \
  --comparison-operator "LessThanThreshold"

# 高コストアラート
aws cloudwatch put-metric-alarm \
  --alarm-name "HighCost" \
  --alarm-description "Cost is too high" \
  --metric-name "BlendedCost" \
  --namespace "AWS/CE" \
  --statistic "Sum" \
  --period 86400 \
  --threshold 100 \
  --comparison-operator "GreaterThanThreshold"
```
