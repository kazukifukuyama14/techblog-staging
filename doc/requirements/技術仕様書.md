# 🟦 AWS + Hugo テックブログ 技術仕様書

## 📋 概要

本ドキュメントは、AWS と Hugo を組み合わせた静的テックブログの構築・運用に関する技術仕様を定義します。コスト効率性、運用の簡素化、インフラのコード化を重視した設計となっています。

## 🎯 目的・背景

### 目的

- 低コストで運用可能なテックブログの構築
- フロントエンド・バックエンド知識が浅い開発者でも運用可能な構成
- インフラのコード化による再現性と保守性の向上
- AWS サービスによる統合管理

### 背景

- 従来の動的 CMS では運用コストが高い
- 静的サイト生成による高速化とセキュリティ向上の需要
- インフラのコード化による運用効率化の必要性

## ✅ コンセプト条件の整理

| 条件                            | 技術選定の方向性                          |
| ------------------------------- | ----------------------------------------- |
| コストを抑える                  | 無料枠や低料金サービスを活用              |
| フロント/バックエンド知識が浅い | GUI や簡単な CLI で操作可能なツールを選定 |
| インフラは Terraform で管理     | IaC（Infrastructure as Code）を前提に構成 |
| インフラは Terraform で管理     | IaC（Infrastructure as Code）を前提に構成 |

## 🛠️ 推奨技術スタック一覧

| 機能                      | 推奨技術          | 理由                                      |
| ------------------------- | ----------------- | ----------------------------------------- |
| 静的サイト生成            | Hugo              | 高速・簡単・Markdown ベース               |
| ストレージ & ホスティング | Amazon S3         | 静的サイトホスティングに最適、無料枠あり  |
| CDN 配信                  | Amazon CloudFront | 高速配信、S3 と連携可能                   |
| IaC 管理                  | Terraform         | AWS 全体をコードで管理可能                |
| CI/CD                     | GitHub Actions    | Hugo ビルド → S3 アップロードを自動化可能 |

## 📁 プロジェクトディレクトリ構成（詳細版）

```bash
techblog-staging/
├── hugo-site/                        # Hugoプロジェクト（静的サイト生成）
│   ├── config.toml                  # Hugo設定ファイル
│   ├── content/                     # Markdown記事
│   ├── layouts/                     # テンプレート
│   ├── static/                      # 静的ファイル（画像・CSSなど）
│   └── themes/                      # Hugoテーマ
│
├── terraform/                       # TerraformによるAWSインフラ管理
│   ├── main.tf                      # メイン設定ファイル（モジュール呼び出し）
│   ├── variables.tf                 # 変数定義
│   ├── outputs.tf                   # 出力定義
│   ├── terraform.tfvars             # 変数値（環境ごとに分けてもOK）
│   ├── provider.tf                  # AWSプロバイダー設定
│   ├── modules/                     # モジュール化された構成
│   │   ├── s3/                      # S3バケット構成
│   │   │   ├── main.tf
│   │   │   ├── variables.tf
│   │   │   └── outputs.tf
│   │   └── cloudfront/             # CloudFront構成
│
├── .github/
│   └── workflows/
│       └── deploy.yml              # GitHub ActionsによるCI/CD（Hugo → S3）
│
├── README.md                        # プロジェクト概要・構築手順
└── LICENSE                          # ライセンス（任意）
```

### 🧩 各ディレクトリの役割

- **hugo-site/**: Hugo で生成する静的サイトのソース。Markdown で記事を書き、テーマでデザインを整える。
- **terraform/**: AWS リソース（S3, CloudFront, IAM）をコードで管理。
- **modules/**: Terraform の構成をモジュール化することで再利用性と可読性を向上。
- **.github/workflows/**: GitHub Actions で CI/CD を構成。記事更新 → 自動ビルド → S3 へアップロード。

## 🗂️ AWS リソース一覧（Terraform 管理対象）

### 🔹 1. 静的サイトホスティング関連

| リソース名                            | Terraform リソースタイプ                           | 用途                                             |
| ------------------------------------- | -------------------------------------------------- | ------------------------------------------------ |
| S3 バケット                           | aws_s3_bucket                                      | Hugo で生成した静的ファイルのホスティング        |
| S3 バケットバージョニング             | aws_s3_bucket_versioning                           | ファイルの変更履歴管理                           |
| S3 バケット暗号化                     | aws_s3_bucket_server_side_encryption_configuration | 保存時暗号化（AES256）                           |
| S3 バケットウェブサイト設定           | aws_s3_bucket_website_configuration                | 静的サイトホスティング設定                       |
| S3 バケットパブリックアクセスブロック | aws_s3_bucket_public_access_block                  | パブリックアクセスの制限                         |
| S3 バケットポリシー                   | aws_s3_bucket_policy                               | CloudFront からのアクセス制御（一時的に無効）    |
| S3 バケットライフサイクル設定         | aws_s3_bucket_lifecycle_configuration              | 古いバージョンの自動削除（30 日移行、60 日削除） |
| CloudFront ディストリビューション     | aws_cloudfront_distribution                        | CDN 配信、S3 との連携                            |
| CloudFront オリジンアクセス ID        | aws_cloudfront_origin_access_identity              | S3 への安全なアクセス                            |
| CloudFront キャッシュポリシー         | aws_cloudfront_cache_policy                        | カスタムキャッシュ設定                           |

## 🔒 セキュリティ要件

### 認証・認可

- 既存の IAM ユーザーを使用（手動で作成済み）
- アクセスキーは定期的なローテーション
- 最小権限の原則に従ったポリシー設定

### 暗号化

- S3 バケットはデフォルトで暗号化を有効化
- CloudFront は HTTPS 通信を強制
- S3 バケットの暗号化（デフォルト）

### ネットワークセキュリティ

- S3 バケットは CloudFront からのみアクセス可能
- パブリックアクセスは必要最小限に制限
