# 📚 AWS + Hugo テックブログ ドキュメント

## 📋 概要

このディレクトリには、AWS と Hugo を組み合わせた静的テックブログの各種ドキュメントが格納されています。staging 環境として、ローカル開発・テスト用途に特化した構成となっています。

## 🤖 ドキュメント作成について

**注意**: 本ドキュメントの大部分は、AI（Claude Sonnet 4）の支援を受けて作成されています。ディレクトリ構成と技術スタックの基本方針のみ、開発者が決定しました。

- **開発者が決定した部分**: プロジェクト構成、技術選定、ディレクトリ構造
- **AI が支援した部分**: 要件定義書、設計書、構築手順書、運用手順書の詳細内容
- **最終確認**: 全ドキュメントの内容は開発者が確認・修正の上、採用しています

## 📁 ディレクトリ構成

```bash
doc/
├── README.md                    # このファイル
├── requirements/                # 要件定義系
│   ├── README.md               # プロジェクト概要・セットアップ手順
│   ├── 技術仕様書.md           # システムの技術的な詳細
│   └── 構築手順書.md           # 段階的な構築手順
├── design/                      # 設計系
│   ├── システム設計書.md       # システム全体の設計
│   ├── インフラ設計書.md       # AWSリソースの詳細設計
│   └── データ設計書.md         # Hugoサイトのコンテンツ構造設計
└── operation/                   # 運用系
    └── 運用・保守手順書.md     # 日常運用とトラブル対応
```

## 🎯 各ドキュメントの役割

### 📋 要件定義系（requirements/）

| ドキュメント  | 内容                                     | 対象者                 |
| ------------- | ---------------------------------------- | ---------------------- |
| README.md     | プロジェクト概要、特徴、クイックスタート | プロジェクト参加者全般 |
| 技術仕様書.md | システムの技術要件、非機能要件           | 開発者、アーキテクト   |
| 構築手順書.md | 段階的な構築手順、トラブルシューティング | 開発者、インフラ担当者 |

### 🏗️ 設計系（design/）

| ドキュメント      | 内容                                               | 対象者                 |
| ----------------- | -------------------------------------------------- | ---------------------- |
| システム設計書.md | 全体アーキテクチャ、データフロー、セキュリティ設計 | アーキテクト、開発者   |
| インフラ設計書.md | AWS リソースの詳細設計、セキュリティ、コスト設計   | インフラ担当者、DevOps |
| データ設計書.md   | Hugo サイトのコンテンツ構造、メタデータ設計        | フロントエンド開発者   |

### 🛠️ 運用系（operation/）

| ドキュメント        | 内容                         | 対象者             |
| ------------------- | ---------------------------- | ------------------ |
| 運用・保守手順書.md | 日常運用作業、監視、障害対応 | 運用担当者、開発者 |

## 🚀 ドキュメントの活用方法

### 1. プロジェクト開始時

1. **README.md** でプロジェクト概要を把握
2. **技術仕様書.md** で技術要件を確認
3. **システム設計書.md** で全体構成を理解

### 2. 構築時

1. **構築手順書.md** に従って段階的に構築
2. **インフラ設計書.md** で AWS リソースの詳細を確認
3. **データ設計書.md** で Hugo サイトの構成を理解

### 3. 運用時

1. **運用・保守手順書.md** で日常作業を実施
2. 各設計書を参照して変更・拡張を検討
3. 必要に応じてドキュメントを更新
